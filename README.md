# 🐭 鼠鼠小助手 ShuShu Tweaks

一个 SillyTavern 第三方扩展，现在装了**两大块功能**（原来是两个扩展，v1.12.0 合成一个）：

| 功能 | 一句话 |
|---|---|
| **思维链收纳** | `<think>` 之类的思维链从正文挪进酒馆原生折叠块，续写不再把思维链吐回正文、格式也不会被冲乱（思维链不删除，点开就能看） |
| **面板工坊** | 把角色管理面板拆成可自由装配的积木 + 8 种角色卡样式 + 详情页版头 + 导入即更新 |

## 功能一：思维链收纳（Thinking Shield）

两层（原设计写了三层，实测这版酒馆缺一层，见下）：

| 层级 | 机制 | 作用 |
|---|---|---|
| 生成前 | `generate_interceptor`（manifest 里声明） | 任何生成（普通 / 续写 / 重 roll / swipe）发起前先清聊天记录，模型拿到的 prompt 永远不带思维链 |
| 存储层 | `MESSAGE_RECEIVED` / `GENERATION_ENDED` / `CHAT_CHANGED` | 生成结束、收到消息、切换聊天时把存量思维链挪进 `extra.reasoning` 并保存；收纳后自动重绘，折叠块就出来了 |
| 显示层（**这版酒馆没有**） | 需要 `messageFormatter.addHook` | 酒馆 1.18.0 没有这个钩子系统（只有 DOMPurify 的 `addHook`），所以流式输出时那个没闭合的 `<think>` 会短暂露一下。**替代方案**：打开酒馆自带「高级格式化 → Reasoning → 思维链标签」，那就是原生的显示层剥离 |

- **思维链不会被删除**：都在消息上方的「思考」折叠块里，点开能看、能复制、能编辑
- 希望续写时模型还能参考之前的思考：酒馆自带「高级格式化 → Reasoning → Add to Prompts」打开即可，和本扩展完全兼容
- 开关 / 标签列表都在抽屉里；**从旧版升级过来的会按你原来的设置来**（旧版 `extension_settings.tavern_tweaks` 自动迁移一次）

## 修过的两次「分页翻车」

**症状**：装配面板里，分页模块"一会儿找不到、一会儿重复出现"。

**真因**：它的布局里分页**同时被放进两个模块**（`工具与分页` 预设 + 自己加的模块）。
一个按钮只有一个原生 DOM，于是每次 `apply()` 都把它从一个模块搬到另一个 —— 看着就是来回跳。
**修法**：`normalizeLayout()` 自愈 —— 一个按钮只保留第一次出现的位置，其余删掉并落盘（只修一次）。

**排查中还踩了一个自己的坑**：我一开始用"文档里所有 `.paginationjs`"来数份数，
结果把**用户人设面板**（`#persona_pagination_container`）那个分页也数进来了，
于是误判成"重复"——**诊断脚本的选择器必须锁死到目标容器**，别拿类名全局数。

> rebuilt 类按钮（酒馆每次重画都会重建 DOM 的，比如**分页**、标签筛选）还有一层坑：
> 我们搬进模块的旧副本**一直是 connected 的**，`resolveNative` 只检查"还在不在 DOM 里"根本发现不了；
> 而且旧的被搬走后，`b.native` 那个带原生父容器的选择器**再也匹配不到它**，清理时必须显式摘掉缓存里那一个。

## 🐭 鼠鼠面板（扁平化设置面板）

设置**不再**挤在酒馆「扩展」列表里那个折叠抽屉里（十几个扩展里根本找不到）。
现在是一个独立的扁平面板：

```
扩展列表 → 🐭 鼠鼠小助手 → [打开鼠鼠面板] → 居中的扁平面板（Esc / 点背景关闭）
```

- **六个分区**：思维链收纳 / 角色卡样式 / 角色详情页版头 / 导入即更新 / 面板装配 / 角色列表排序
- **扁平**：不用渐变、不用高光、不用多层阴影；靠「发丝分隔线 + 一点点底色」分区
- **控件自己画**：扁开关（`appearance:none` 的胶囊）、扁平滑块、扁平输入框 / 下拉
- **跟着主题走**：颜色全用 `--SmartTheme*` 变量，强调色取 `--SmartThemeQuoteColor`（所以你这套红调主题下面板也是红的）
- 一行一个设置：左边标题（带小字说明）、右边控件；改完立刻生效并落盘，不用点保存
- 窄屏（<560px）自动铺满、行内控件换行

### 踩坑记录（都写在代码注释里了）

| 坑 | 现象 | 解 |
|---|---|---|
| flex 子项默认 `min-height:auto` | 面板内容把容器顶出屏幕（顶到视口外 460px），顶部一大截看不见 | `.ssp-p-body { flex:1 1 auto; min-height:0 }` —— 不加这句 `overflow-y:auto` 形同虚设 |
| `top:50% + translate(-50%,-50%)` 被级联吃掉 | 计算出来 `top:0`，面板整个跑到视口上方 | 改成**根节点 flex 居中**（`position:fixed; inset:0; display:flex; align-items:center`），不去跟 `top` 较劲 |
| 面板文案里写 `**加粗**` | 面板上原样显示星号（这不是 markdown 渲染器） | 用 `<b>` 标签 |
| 面板背景直接用 `--SmartThemeBlurTintColor` | 这个变量带透明度 → 后面聊天文字透出来，看着很脏 | `color-mix()` 掺黑做实（≈95%），遮罩也加深到 .62 |

## 功能二：面板工坊

把酒馆的**角色管理面板**拆成可自由装配的积木：

```
按钮（原子）  →  模块（容器，可 1~2 层，每层放任意按钮）  →  分区（头部 / 列表 / 底部栏）
```

模块之间可以互相换位置，模块内可以随意增删按钮，**桌面和手机是两套完全独立的布局**。
不装配的时候，面板和酒馆原版**长得一模一样**（我们不加自己的框、底色和边距）；
一键「恢复原版」把布局还原成默认，总开关一关则把 DOM 精确还原回原样。

> **v0.3.0** —— 从「区块开关」升级成「积木装配」。装配界面**内化在面板里**
> （一根细条入口 + 展开成一个方框），不是浮层、不是第二个界面。

## 装在哪

只放一份，就是这个目录：

```
data/default-user/extensions/ShuShuPanel/
```

⚠️ **绝对不要**再往 `public/scripts/extensions/third-party/` 放一份副本 ——
同名会被遮蔽（改了不生效），不同名会被**加载两次**。

## 怎么用

1. 打开酒馆右侧的**角色管理面板**
2. 面板顶部按钮条的下面有一根细条：**`▦ 装配面板`** → 点它展开装配方框
3. 在方框里装配：

   | 操作 | 怎么做 |
   |---|---|
   | **换位置** | 拖模块头的 `⠿` 手柄；或点模块上的 `⇅` 送到另一个分区 |
   | **换顺序** | 拖模块到目标位置；或点模块头上的 `▲▼` |
   | **显示 / 隐藏** | 模块头上的小滑块（关掉＝这个模块从面板上消失，配置还留着） |
   | **加按钮** | 从底部「备选池」把按钮**拖进**模块的某一层 |
   | **拿掉按钮** | 点按钮上的 `✕`（回备选池，不是删除） |
   | **切 1 层 / 2 层** | 模块头上的 `1层 / 2层` |
   | **靠左 / 居中 / 靠右** | 模块头上的 `⇤ ↔ ⇥`（每个模块独立设置，底部栏默认居中） |
   | **换层** | 拖按钮到另一层；或点按钮上的 `⇅` |
   | **改名字** | 点模块名，直接改 |
   | **加模块** | 点「＋ 新建模块」，然后拖到想要的分区 |
   | **删模块** | 点模块上的 `🗑`（里面的按钮全部回备选池） |
   | **恢复原版** | 方框右上角「恢复原版」＝ 把当前设备的布局还原成默认（看着和原版一致） |
   | **手机上装** | 用手机打开装配面板装一次 —— 手机布局是独立存的 |
   | **看清模块边界** | 展开装配面板时，面板上的每个模块会被描一圈虚线（`outline`，不占地方）；**一收起就完全看不出来** |

4. 兜底入口：**用户设置 → 扩展 → 🐭 鼠鼠面板工坊** → 「展开装配面板」

> 改一下，**面板当场就变**，不用点确定、不用刷新。

## 角色卡样式（可选，默认开着「封面渐隐」）

**在哪里切换：用户设置 → 扩展 → 🐭 鼠鼠面板工坊 → 最下面的「角色卡样式」**

- 下拉框：**原版（不改动）** + 8 种样式 —— 封面渐隐 / 侧图渐隐 / 双列封面 / 单行紧凑 /
  悬停展开 / 叠层相册 / **歌单行**（网易云那种一行一首：序号 + 方块封面（左下角小角标）+
  名字 / 标签·简介 + ★ 收藏 + 右侧版本号；整块列表铺渐变、行悬停提亮、行间一条细线。
  **封面和文字跟着「卡片高度」自适应缩放**（56px 行→40px 封面，150px 行→108px 封面）；
  **那颗 ★ 是能点的**：灰星=没收藏、金星=已收藏，点一下直接收藏/取消；
  **列表底色可以自定义**（抽屉里的「歌单底色」颜色选择器）。原来那个「光环头像」已经换成它了）
  / **学生证**（扁平证件卡：顶部灰带左边「学生证 · 校名」、
  右边「student ID · 列表序号」；左半边白边证件照，右半边一道淡淡的侧边渐隐角色图影子；
  中间一行一个字段「姓名：角色卡名 / 班级：标签 / 学号：No.序号」；右下角纯 CSS 条形码；
  底部灰带「有效期 年份-09 / 仅限本人使用，不得转借」）
- **高清头像**（默认开）：酒馆 `getThumbnailUrl('avatar')` 给的是 **96×144** 的缩略图，
  铺满整行必然糊，所以这里把 `<img>` 换成 `/characters/<文件名>`（原图），并加 `loading="lazy"`。
  关掉就换回缩略图。
- 参数旋钮：卡片高度 / 圆角 / 卡片间距 / 名字字号 / 简介字号 / 渐隐强度；取景：偏上·居中·偏下；
  内容对齐：靠左·居中·靠右；学生证可填校名 / 年份，并切换**证件配色**（纸白 / 牛皮 / 暗夜）。
  ⚠️ 学生证**不吃「渐隐」旋钮**：证件照要完整（它自己的"影子"是右半边那道淡淡的水印）。

实现要点：

| 做法 | 原因 |
|---|---|
| 样式注入成 `<style id="ssp_card_css">`，**不写进 user.css** | 能实时切换；注入点在 `<head>` 末尾，同权重稳压酒馆自带样式 |
| 样式本体与选项**分开生成**（`CARD_STYLES` + `CARD_OPT`） | 旋钮才能自由拼装；参数一律 `var(--pv-*, 默认值)` |
| 抽屉的类名一律 `ssp-c*` 前缀、**不借酒馆的 `checkbox_label`** | `.ssp-knob` 是装配面板开关滑块的**圆点**，撞名会把圆点顶出轨道（就是那次"开关错位"） |
| 关掉（选「原版」）→ 撤 `style` 标签 + 头像还原 | 一点痕迹不留；总开关关掉时也一起撤 |
| 「卡片间距」「卡片高度」8 种样式都必须吃（末尾补兜底规则） | 曾经有样式把间距/高度写死（单行紧凑 2px、叠层相册 -16px、双列封面用 aspect-ratio），那几个样式下拖旋钮没反应 |
| 每种样式带一份**出厂参数**（`CARD_STYLE_META`） | 切样式时"没动过的旋钮"跟着新样式走、"自己调过的"保留；高度还分 height / min-height / 比例缩放三种用法 |
| `reclaim()` 里重新应用 | 酒馆每次重画列表都会换回缩略图、丢掉样式 |
| 文件名从现有 `src` 的 `file=` 参数里取 | 不依赖 `data-chid`，也不依赖 title 属性 |
| `body.charListGrid` 接管成两列封面墙 | 酒馆的 ▦ 网格模式权重不低，会把卡片压成 100px 方块并隐藏简介/标签 |
| 学生证里名字块 `.character_name_block` 必须是 `position:static` | 「学号」那行是名字块的**儿子**，名字块一旦是定位元素就成了它的包含块，学号会锚在名字块上 —— 卡片一改高度就飘到内容区（一度表现为"student ID 跑到白底上看不见"）。名字块本身是 flex 子项，去掉定位后 `z-index:1` 照样生效 |
| 歌单行的「第二行简介」由 JS 洗好塞进 `--ssp-line` | CSS 里拿不到元素文字；`content:var(--ssp-line)` 才能加省略号。头像一个道理（`--ssp-avatar`） |
| 歌单行的 ♥ 用 `display:flex !important` 压掉酒馆给非收藏卡写死的 `display:none` | 顺带把「不显示收藏标记」那个开关也改成 `.ch_fav_icon{display:none !important}`，否则压不过样式本体 |
| 列表上点 ★ 收藏：监听挂在列表的**捕获阶段** | 酒馆自己的「点卡片选角色」是 `$(document).on('click', '.character_select')`（冒泡阶段、挂在 document 上）。只有捕获阶段先接住再 `stopPropagation`，才做得到"只收藏、不打开角色" |
| 收藏走 `/api/characters/merge-attributes`（fav 字段），不自己写存档 | 和角色右键菜单那条「收藏」是同一条路；请求头用 `getRequestHeaders()`（带 CSRF），失败只弹提示、不动 UI |
| 详情页版头的排版规则一律 `!important` | 实测酒馆（+美化里的自定义 CSS）会把 `#avatar_controls` 变成 `flex-direction:column`（按钮排竖成 499px 高）、把 `#avatar_div` 顶出面板。这几条是纯排版，压过去不影响功能 |
| ⋯ 按钮**不用** `showPicker()`，而是把原生 `select` 铺满 + `opacity:0` | Chrome 对 `display:none` 的 `select` 调 `showPicker()` 会抛 `InvalidStateError`，兜底一显示就变成"先冒出下拉栏、再冒出选择框"。透明但照常渲染的 `select` 直接点就弹原生菜单，一行 JS 都不用 |
| `#rm_button_selected_ch` 那颗《 插在 `h2` 前面 | 酒馆的名字是 `<div id="rm_button_selected_ch"><h2>名字</h2></div>`；插进去就自然排在名字左边，不用另找位置 |
| 字段解析里 `?<![\\w$]` 这个前置断言不能省 | 不然单行 JSON 会被从 `me:` 处切开 —— `name` 只剩 `me`，`gender` 只剩 `er` |
| 还原时**先放回原生元素、再摘自己加的节点** | 反过来会出人命：`#avatar_controls` 里那个「查看所有标签」按钮跟着我的工具栏一起被 `.remove()`，脱离 DOM 之后就再也查不到了 —— 关一次开关按钮就永久消失。顺序换过来就没事 |
| 头像框 `#avatar_div_div` 的 `height` 必须显式写成 `auto` | 酒馆给它写死了 `height:90px`：在视频页皮里图被撑成 16:9（244px）却只在框里占 90px，**溢出部分压住了下面的标题/按钮**。宽高都要重置 |
| 视频页的 Token 数要延后补一次 | 那个数字是酒馆异步算的，刚点开多半还是 0 → 我在 1.2s / 3s 各补刷一次 |
| 「先清理旧的、**再**建新的」 | 我一开始写反了：先 `buildVideoTopbar()` 建好，紧接着那行"清掉上一轮的 `.ssp-vid-bar`"又把它删了 —— 页面里表现就是"顶栏死活不出现"，不报错。顺序换过来就好了 |
| 拆自己造的外壳之前，先把住在里面的酒馆原生元素救出来 | 视频页顶栏里搬进了 `#result_info`（Token + 那排图标）。下一轮重建时，如果先 `.remove()` 整个顶栏，`#result_info` 就跟着脱离 DOM，`getElementById` 再也找不到它 → 新顶栏里就少了那排按钮。现在拆之前先按 `__sspHome` 放回去 |
| 同一个坑踩了第二次：⋯ 的下拉壳被搬进「视频页那块」 | 那块每轮重建，⋯ 就跟着被摘走 → 表现是"⋯ 按钮凭空消失、更多…菜单点不到"。现在拆 `\.ssp-vid-extra` 之前也会先把 `.ssp-detail-more-holder` 救回按钮排。**规律：只要把酒馆的元素搬进自己造的容器，拆容器前就必须先救它出来** |
| 想改按钮顺序，用 CSS `order` 而不是搬 DOM | 那排图标是 `.form_create_bottom_buttons_block` 的子元素；先把它设成 `display:flex`，再用 `order:1/11/21/99` 分组排序 —— DOM 一个节点都没动，还原天然干净 |
| 「更多…」不能放在横向滚动区**里面** | 第一版把 ⋯ 放在胶囊排末尾，那排一溢出它就滚到屏幕外 —— 用户反馈"更多在哪看啊，我找不到"。现在套一层 `.ssp-vid-actionbar`：滚动区 `flex:1 + overflow-x:auto`，⋯ 是它的兄弟、`flex:0 0 auto`，永远可见 |
| **窄面板里宁可换行，也别做横向隐藏** | 修 ⋯ 的时候我把胶囊排留成了 `overflow-x:auto`，结果"删除"那颗也滚出去了 → 又收到一句"你咋把我删除角色卡的功能弄没了"。教训：面板就这么宽（~430px），**任何"藏起来要滑一下"的设计都等于没有** —— 直接 `flex-wrap:wrap` 让它换行 |
| `callGenericPopup(内容, 类型, 输入框默认值, 选项)` —— **选项是第 4 个参数** | 写到第 3 个会被当成"输入框默认值"丢掉 → 自定义按钮不出现、退化成系统默认的「确定/否」。真机上表现为"弹了个没用的框" |
| `POPUP_RESULT.CUSTOM1/2 = 1001/1002`（不是 2/3），`POPUP_TYPE.CONFIRM = 2`、`INPUT = 3` | 我一开始按 2/3 猜，返回值和比较永远对不上 → 用户点按钮等于取消。而且 CONFIRM 里那颗「确定」= `AFFIRMATIVE(1)`，要做成和默认动作一致（我让它等于"更新"） |
| 读 PNG 里的卡数据：**base64 → 必须按 UTF-8 解码** | 直接 `atob` 出来的是 Latin-1，中文姓名会变成「ä½ å」这种乱码（实测 6 张卡全中招） |
| 卡数据的边界要用 **PNG 块长度**，不能让正则吃到块尾 CRC | 块结构 `[长度:4][类型:4][数据:长度][CRC:4]`，关键字在数据开头 → `数据 = slice(关键字, 关键字+长度)`。让正则一路吃到 CRC 的话，那 4 字节可能也是 base64 字母 → 长度对不齐 → `atob` 报 "not correctly encoded"（两张最大的卡就是这么读空的） |
| base64 解码时把 `=` 全部去掉、再按长度 %4 对齐 | 按"第一个 `=`"截断看着更聪明，但只要正文里带 `=` 就会截早 → JSON.parse 直接挂 |
| V3 卡：**`data.name` / `data.description` 才是当前值**，顶层那份是旧的 V2 镜像 | 实测顶层写着「🦴几许人是惊世才5.10」，`data.name` 才是「岑几许」 |
| 有些卡的 JSON 里是**裸控制字符**（别的工具导出的非法 JSON） | `JSON.parse` 到一半就断。加了个字符串感知的修复：只在字符串内部把 <0x20 的字符转义，结构空白不动 |
| 人设正文不一定在 `description` | 有的卡写在 `personality` 里 → 比对时两边都试，取高的那个 |
| 导入完，**内存里的角色对象还是旧的** | 更新卡之后直接读 `ctx.characters[i].data.extensions` 拿到的是**旧**对象（配套数据还在里面）→ 我一看"没丢"就跳过补写，实际盘上早被覆盖了（真机实测：局部正则/世界书/深度提示全没）。补写前必须 `await getCharacters()` 重取一遍 |
| 新卡里可能带着**空的默认字段** | 导入后 `data.extensions.depth_prompt` 会是一个 `{prompt:'',depth:4,role:'system'}` —— 只看"有没有这个对象"会误判成"新卡给了值"，得看 `prompt` 是不是空的 |
| 无头 Chrome 里点 `dialog.popup` 的按钮**不生效** | 用 `Input.dispatchMouseEvent` 点弹窗按钮试了两次都是"假成功"（其实没点中，弹窗还开着）→ 验证流程时把弹窗 stub 成直接返回结果，弹窗渲染另外单独验。**别相信"看起来通过了"的交互验证，要用能被证伪的检查点**（比如让第二遍导入的内容真的不同，再看描述变没变） |
| 灰带一律用 `inset box-shadow` 画，不用 `border` | 卡片 `overflow:hidden` 会把 border 连同文字一起裁掉 |
| 证件照、学号行都不写死 px，一律按 `var(--pv-h)` 算 | 卡片高度旋钮 40–420 全程都对齐，不用二次校准 |

**18 个控件**（每个各占一行）：样式 1 · 高清 1 · 滑块 6（渐隐强度 / 卡片高度 / 圆角 / 卡片间距 /
名字字号 / 简介字号）· 下拉 5（图片颜色 / 渐隐方式 / 取景 / 内容对齐 / 证件配色）· 勾选 5
（高清 + 简介 / 标签 / 版本号 / 收藏标记）· 学生证校名与年份。

样式数据在 `index.js` 的「生成区」里，**从 `角色卡美化-原型.html` 生成**，别手改。

## 导入即更新（把「导入」「替换/更新」「从 URL 导入」合成一条路）

**默认开着**。点原来那颗「导入」（或「从 URL 导入」），走的是合并后的流程：

```
选文件 / 拖进来 / 贴 URL
   ↓
认卡（三档，从准到糙）：
   ① 卡里的姓名（`data.name`，V3 那份才是当前值）
   ② **人设/描述文字重合度 ≥ 阈值（默认 60%）** ← 改名、改标题、装饰名也能认出来
   ③ 卡里啥都读不到，才退回文件名
   ↓
认出来已有这张卡 ──→ 问一次：[ 更新这一张 ]  [ 另存为新角色 ]  [ 取消 ]
                     更新 = 保留聊天 / 素材 / 群组 / 标签，角色数据按新文件覆盖
没认出来（新卡） ──→ 直接导入，什么都不弹
   ↓
toast「导入完成：1 张更新 / 2 张新增」+ 列表自动刷新（**不会自动打开那张卡**）
```

⚠️ **如果②是靠文字重合认出来的、但两边姓名不一样**，弹窗里会多一句橙色提醒
（"可能只是模板相似，不确定就选另存为新角色"）—— 实测两张不同的多角色调度卡能到 **61%**，
所以真心建议：这种模板卡多的话把阈值调到 **75%** 左右（抽屉里那个「人设重合度」滑块）。

**为什么原来那么烦**：酒馆的「导入」和「更多… → Replace/Update」打的其实是**同一个接口**
`POST /api/characters/import`，区别只在有没有 `preserved_name`：
- 不带 → 服务端 `getPngName()` 自动去重，同名卡变成 **`池尚早1.png`**（于是库里多一张）
- 带 → 原地覆盖（头像名不变，而标签是按 avatar 名挂在 `tag_map` 上的 → **标签自然也还在**）

所以合并只要做对一件事：**先认出这张卡是谁**，再决定带不带那个参数。

- 更新前会先记下这张卡原来的标签，更新后核对一遍；万一有标签没保住，会提示你哪几颗丢了
- 想要真·另存为新的，在弹窗里选「另存为新角色」就行（不会误覆盖）
- 关掉：抽屉里的 **「导入即更新」** 开关，一关就完全回到酒馆原样（我们的监听整个摘掉）

### 更新一张卡时，哪些"配套数据"会保住

酒馆的「替换 / 更新」本质是**用新文件整个覆盖旧卡**，所以有些东西会跟着没 ——
那些"看着像跟着角色走、其实存在卡里"的字段最容易丢。现在更新完会自动补回来：

| 数据 | 存在哪 | 更新后 |
|---|---|---|
| 聊天记录 | 按 `头像名.jsonl` 存 | ✅ 保住（头像名不变） |
| 群组归属 / 人员 | 按头像名 | ✅ 保住 |
| 标签 | `tag_map[头像名]` | ✅ 保住（更新后还会核对一遍，丢了会提示） |
| **局部正则** | **卡里** `data.extensions.regex_scripts` | ✅ **并集补回**（新的在前，旧的按 id/scriptName 去重后补上） |
| **收藏 ★** | **卡里** `data.extensions.fav` | ✅ 旧的是收藏就恢复（顶层 fav + 扩展 + 列表星标一起写） |
| **世界书绑定** | **卡里** `data.extensions.world` | ✅ 新卡没绑 → 用旧的兜住；新卡绑了 → 听新卡的 |
| **深度提示词** | **卡里** `data.extensions.depth_prompt` | ✅ 同上（新卡里那个空 prompt 的默认值不算"有"） |
| 话痨度 | 卡里 | ✅ 同上 |
| 角色设置覆盖 / 预设绑定 | `extension_settings`（按头像名） | ✅ 保住（不在卡里） |
| 卡里的正文/人设/开场白 | 卡里 | ⚠️ **按新文件覆盖**（弹窗里写明了） |

写回用的是酒馆自己的 `writeExtensionField()`（正则扩展存局部正则就是走它），
底层 `merge-attributes` 的 `deepMerge` 对数组是**整体替换**（`isObject` 排除了数组），不会把数组揉成对象。

### 皮一：About. 字段列（默认）

**点开一个角色卡之后**那个「编辑 / 详情」面板，原本是：小头像 + 一排按钮 + 「更多…」下拉。
现在排成（**只动排版，功能一个不少**）：

- **⋯ 按钮**就是原来那个「更多…」下拉本身：`select` 被铺满、设成透明，外面套一层画着 ⋯ 的壳，
  所以点下去弹出的是**系统原生菜单**，选项一个没少（不是重写的假菜单）。
- **标签区**也顺手重排了：
  ```
  [即兴坠落 ⊗]                        [🏷] [🔍] [+]
  ```
  标签芯片**靠左**排、每颗右边的 **⊗ 一直是亮的**（点了就从角色卡上删掉，走的是酒馆自己的
  `.tag_remove` / `onTagRemoveClick`，不是我们另写的）；右边三颗按钮：🏷 是酒馆原来的

### 操作区收纳（两套皮共用）

原本这里挤着 **14 个带边框的小方块**：⋯ + 8 颗图标 + 标签区 3 颗，所有东西一样重、还分成三行。
现在按「轻量整理」收拾了一遍：

```
[即兴坠落 ⊗]                        [🏷] [🔍] [＋]     ← 标签行：芯片居左，按钮去框
──────────────────────────────────────────────
★  🌐  📇   │   📖  🙂   │   📤  ⧉  ☠        ⋯     ← 操作行：无框 + 三组分隔 + ⋯ 最右
用这张卡         编辑资料         文件操作
```

- **去框**：平时只剩图标，指上去才浮出淡淡底色；标签区那三颗同理
- **分组**：按用途排成三组（用这张卡 / 编辑资料 / 文件），组间一条 1px 竖线
  —— 实现是给每组第一颗加 `border-left` + 用 CSS `order` 重排（**不动按钮的 DOM 位置**，
  所以点击逻辑、还原都还是酒馆原来那条路）
- **⋯ 归位**到最右（以前被放在最左，反直觉）
  ⚠️ 视频页里那条胶囊排是**横向滚动**的，⋯ 要是跟着一起滚就会被挤出屏幕、用户根本找不到
  （真实翻车过）。所以它被放在滚动区**外面**（`.ssp-vid-actionbar > [滚动区] + ⋯`），永远露着，
  滚动区右边缘还加了一道渐隐提示"右边还有东西"
- **☠ 删除**单独标红，不再和 📖 一样重
- **视频页里酒馆那排图标收起来**：功能全在胶囊排里（胶囊从 6 颗补到 **8 颗**，
  补上了「聊天书」「人物」），不再重复两遍；⋯ 也跟着胶囊排走
  ⚠️ 胶囊排**必须自动换行、不能横滑**：面板只有 ~430px，一排放不下 8 颗，
  第一版做成 `overflow-x:auto` 之后，最后几颗（导出 / 复制 / **删除**）滚到屏幕外 ——
  用户直接来问"你咋把我删除角色卡的功能弄没了"。现在 `flex-wrap:wrap` + `overflow:visible`，
  8 颗永远都看得见；危险的那颗（删除）单独标红

## 手动排序（拖拽自定义顺序）

酒馆自带的排序是按字段（A-Z / 最新 / 收藏…）；这个是**你自己的顺序**。

- **怎么进**：用户设置 → 扩展 → 🐭 鼠鼠面板工坊 → 「手动排序」→ **进入拖拽排序**
  （面板上的入口是「手动排序」按钮；它会进备选池，想放在面板上就把它拖进任意模块）
- **怎么用**：进模式后面板顶部出现提示条，卡片有红色虚线框 —— 直接拖；手机**长按 250ms** 再拖
- **怎么存**：松手即保存。顺序按**头像文件名**记，酒馆重画 / 翻页 / 重启后都会重新套用
- **不在表里的角色**（比如新导入的）保持酒馆自己的顺序、排在后面
- 「按我的顺序」勾选框可以临时关掉；「清空我的顺序」恢复成酒馆排序

> 限制：酒馆一页只渲染 N 张卡（默认 50），所以**只能拖当前页里看得到的卡**。
> 换页后其它卡会按它们在自己那一页里的相对位置接着排。

## 四个新增按钮都干什么

面板原生没有这四个，是本插件加的（装配界面里带绿色「新增」徽标）。
它们**不重写酒馆的逻辑**，只去点酒馆自己的入口：

| 按钮 | 点了会发生什么 | 走的是酒馆哪个入口 |
|---|---|---|
| 🕘 最近聊天 | 列表按「最近聊天」排序 | `#character_sort_order` 选 Recent（等于你自己去下拉框选一下） |
| 🔖 收藏夹 | 只看收藏 / 再点一次取消 | 点它自己那个「只看收藏」圆形筛选钮 |
| 🎲 随机抽卡 | 从角色库里随机抽一张，直接开聊 | `selectCharacterById()` |
| 📊 库统计 | 弹出「N 个角色 · N 个收藏 · N 个标签」 | `getCharacters()` |

## 设计要点（为什么它不容易出事）

| 做法 | 原因 |
|---|---|
| **零 `import`**，依赖全部来自 `SillyTavern.getContext()` | 酒馆改模块路径也不会把它搞挂 |
| **使用态零装饰**（`.ssp-live` 上 `border:0/padding:0/margin:0`） | 面板和原版连成一片；装配界面里的同名单框是另一套选择器，互不干扰 |
| **装配态只用 `outline` 描边** | `outline` 不参与布局 —— 开关装配面板时面板本身一动不动 |
| **底部栏挂在 `.scrollableInner` 上 + `sticky`** | 面板真正滚动的是它（`#rm_characters_block` 高度只等于内容，在那儿 sticky 钉不住）。sticky 仍占文档流位置，所以不会盖住最后一个角色卡 |
| **新增按钮只去点酒馆自己的入口** | 最近聊天=改排序下拉框、收藏夹=点它自己的筛选钮、随机抽卡=`selectCharacterById` —— 酒馆改实现我们跟着变 |
| **升级要照顾已存的旧配置** | 已经打开过的浏览器不会吃到新默认值 —— `SCHEMA_VERSION` 3→4 时会检测「p6 还是不是 v3 那副空样子」，是就升级，用户动过就绝不覆盖 |
| **选择器必须唯一**（`#charListFixedTop .rm_tag_controls`） | `index.html` 里有 **3 个** `.rm_tag_controls`，裸类名会搬错那个，面板上冒出两排一样的标签 |
| **搬家前先拍「父容器 children 快照」** | 还原时按快照顺序 `append` 回去，顺序、位置、连元素上原有的 inline 样式都精确复原 |
| **顺序靠真 DOM 移动，不用 CSS `order`** | 跨容器换位也能做；酒馆自己的事件绑定都是委托式的，跟着节点走 |
| **不给自己造的节点拍快照** | 否则还原时会把按钮塞回槽位（v0.3 开发中踩过的坑，已修） |
| **`apply()` 幂等** | 已经就位的什么都不做；找不到的元素安静跳过 |
| **`elCache` + `reclaim()`** | `.paginationjs`、`.rm_tag_controls` 会被酒馆重画；旧节点断开就重新查询、把新的认领回来 |
| **拆模块容器前先把按钮送回原父容器** | 否则按钮会跟着容器一起被摘掉 |
| **选择器找不到就跳过** | 酒馆更新改了 DOM，最坏是"这个按钮消失"，不会白屏 |
| **触摸端自己实现拖拽**（pointer 事件 + 长按 250ms + elementFromPoint 落点） | HTML5 拖放在触摸屏上**根本不触发**，手机上否则没法把按钮拖到别的模块；另外提供「点选搬运」（点按钮 → 点目标层） |
| **触摸端没有 hover**：`@media (hover:none)` 把"悬停变彩"改成直接彩色、"悬停展开"改成直接展开 | 否则手机上照片一直半灰、「悬停展开」永远展不开 |
| **`@media (pointer:coarse)` 放大所有可点目标** | 桌面上的 14px 小图标手指点不中 |
| **卡片必须 `flex-shrink:0`** | 角色列表是「列方向 flex 容器」且只有 ~568px 高：不钉住的话浏览器会把每张卡压缩到装得下（实测压成 79px），高度旋钮就完全失效 —— 这个只在真酒馆里能复现 |
| **`.tags_inline{flex-basis:auto}`** | 酒馆 `tags.css` 给它设了 `flex-basis:100%`，在定高卡片里会把一排行标签撑成 119px |
| **装配界面是面板内的普通 DOM** | 位置永远跟着面板走；不用 `position:fixed`（那个在面板未展开时会跑到左上角） |
| **CSS 全部 `.ssp-` 前缀，无全局 `!important`** | 不和酒馆本体、也不和美化 CSS 打架 |

## 已知取舍

- 面板里**常驻一根细条**（`▦ 装配面板`）。这是"随时能装配"和"装完零变化"之间的取舍。
- **「列表」是锁定的**：角色列表本体是内容，不作为模块参与装配。
- **备选池里的原生按钮会从面板上隐藏**（否则"拿掉"就没意义了）。默认布局把所有原生按钮都装进了模块，
  所以刚装完的面板和原版一致。
- **手机端默认关掉三个模块**（面板头部 / 标签筛选 / 工具与分页），给列表腾地方 —— 手机上可以自己打开。

### 叠层相册：被压住的标签不再透出来（v1.12.8）

只给 `.avatar` 做 mask 是不够的 —— **标签是文字层，不受那个 mask 管**，
所以下面那张卡被压住的「标签」照样浮在上面（用户原话：「标签为什么叠压了还能透出来」）。

修法：把 `--pv-vis`（露出来的那一截）提到卡片上，图片渐隐和**整体裁剪**共用同一个值：

```css
.character_select{ --pv-vis:calc(100% - var(--pv-overlay,20) * 1%);
  clip-path:inset(0 0 calc(100% - var(--pv-vis)) 0); }   /* 叠压线以下整张裁掉：标签/简介一起收住 */
.character_select:hover{ clip-path:none; }                 /* 悬停取消裁剪 → 整张完整 */
```

> 规律：**分层做的效果要分层检查**。图片层做了渐隐，不代表文字/标签层也会跟着收 ——
> 谁在叠压区里，谁就得自己负责藏起来（或者干脆在容器上裁一刀，一劳永逸）。

### 卡片免疫层：不再跟着「头像形状」走（v1.12.9）

**现象**：酒馆把头像设成圆形时，角色卡列表整张卡跟着变成大弧线。
**真因**：酒馆默认（`avatar_style = ROUND`）有一条

```css
body:not(.big-avatars) .avatar img { border-radius: 50%; }
```

而我们的卡片样式是**铺满头像元素**的（`.avatar` 就是整张卡的底图）→ 头像一圆，卡片就圆。

**修法**（用户选的是"只挡已知泄漏源"，颜色字体继续跟随主题）：

```css
#rm_print_characters_block .character_select .avatar img,
#rm_print_characters_block .character_select .avatar img.pointer{
  border-radius:inherit !important; border:0 !important;   /* 各样式给 .avatar 设多少，图片就继承多少 */
}
```

实测：图片圆角从 `50%` 变成 `12px`（= 卡片的 `--pv-radius`）✓。
颜色 / 字号 / 阴影一律没碰，所以卡片依旧跟着主题配色走。

> 排查提醒：这条 50% 一开始我在**扩展**和**酒馆 CSS** 里都没搜到，最后是在**原型的模拟基础样式**里
> 看到同款写法的 —— 原型是照着酒馆默认写的基础样式，正好把酒馆那条也复现了。
> 以后再遇到"样式莫名跟着变"，先去看原型的基础段（它就是我们当初抄酒馆默认的地方）。

### 修：切换层数后按钮/模块「莫名其妙消失」（v1.12.12）

**真因**（`ensureModuleEls` 里拆多余层那段）：

```js
while (rec.rows.length > m.rows.length) {
    rec.rows.pop().remove();      // ← 把这一层连里面的原生按钮一起 remove 了
}
```

「2 层 → 1 层」（装配面板里的层数切换 / 恢复行数）时，第 2 层里的按钮**没先送回老家就被连窝端** ✗ ——
元素从 DOM 上彻底消失，`resolveNative()` 再也查不到 → 该模块判定为空 → 连模块一起 `display:none` ✗。
一个根因、两个症状（按钮没了 + 模块没了），正是用户报的那句话。

**修法**（和"删模块"那条路一样的写法：拆容器前先把原生元素救出来）：

```js
const row = rec.rows.pop();
Array.from(row.children).forEach(el => {
    const home = originalParentOf(el);
    if (home && home.isConnected !== false) home.append(el);
});
row.remove();
```

实测：p3 走一遍 2层 → 1层 → 2层，`character_sort_order` / `rm_button_search` / `character_search_bar`
**全程都在**，分页也在 ✓。

> 行为说明：2 层 → 1 层会把两层的按钮**合并到第 1 层**（配置语义如此），再切回 2 层时**第 2 层是空的**，
> 按钮都还在第 1 层 —— 不会丢，但要自己再拖一个进去。想让"切回 2 层"记住原来的拆分，说一声我加。

> ⚠️ 测量的坑（这次连踩两次）：我一开始用 `.menu_button, [id^=ssp_btn_]` 数"模块里有多少按钮"，
> 结果把**搜索框、排序、分页**这些不是 `.menu_button` 的元素全漏了 ✗，于是误判"你的布局已经坏了"。
> **数控件别按 class 猜，要按配置里的按钮 id 去对**（或者干脆数所有子元素）。

**改法（只动 CSS + 一次测量，不搬 DOM）**：

## 🔄 面具页实时刷新 · v1.17.1 修复

**问题**：在面具页点了「换成这个」，面板上的「当前」不跟着动，得关掉面板再打开才看得到。

**原因**：切换是**异步**的 —— 我点完酒馆自己列表里那一项后立刻重画面板，可那时候酒馆还没把选中状态落下来，
我读到的还是旧值，所以画面是旧的。

**修法**：挂酒馆自己的事件，而不是猜时机。

| 挂的事件 | 什么时候刷 |
|---|---|
| PERSONA_CHANGED | 换面具（包括在酒馆自己的面板里换） |
| PERSONA_CREATED / UPDATED / RENAMED / DELETED | 新建 / 改描述 / 改名 / 删面具 |
| CHAT_CHANGED | 切聊天（可能连带换绑定的面具） |

事件到了就刷，而且**刷两次**（60ms 和 400ms），因为事件刚发时酒馆可能还没把 .selected 落下来。
另加一个 MutationObserver 兜底：盯着酒馆面具列表的 class 变化，面板开着就跟着刷。

实测：面板开着 → 点「换成这个」→「当前」**当场**就变 ✓（不用关面板）；在酒馆自己的面板里换，我这儿也跟着变 ✓。

## 🐞 存档栏读档 bug 修复 · v1.21.1

## 📌 悬浮球贴边 + 跟着窗口走 · v1.23.1

**问题**：球不贴边；把窗口拉小，球不跟着走（会跟边缘脱开、甚至跑出屏幕）。

**原因**：位置存的是**绝对像素** {x, y}。窗口一变，这个像素坐标还是老值 → 相对边缘的距离就变了。
而且当时**根本没有 resize 监听**（我早前想加，锚点没匹配上，静默跳过了）。

**修法**：位置改成存**离右边 / 下边的距离** {right, bottom}

- 初次 / 拖动结束：都换算成离边距离再存
- 加 resize 监听：按离边距离重算 left/top，并 clamp 在视口内
- 兼容老数据：老的 {x,y} 会自动换算一次；算不出来就当没存过（回默认 右18/下96）

实测（同一页面依次改视口）：

| 视口 | 距右 | 距下 | 屏内 |
|---|---|---|---|
| 1200x900 | 18 | 96 | ✓ |
| 700x600 | 18 | 96 | ✓ |
| 480x760 | 18 | 96 | ✓ |
| 1200x900（拉回） | 18 | 96 | ✓ |

> 顺带记一笔：这次能发现"resize 监听其实没加上"，是因为之前那次补丁的锚点没匹配、脚本静默跳过了。
> 所以现在补丁脚本都要求「锚点必须找到，否则报错退出」—— 不再允许悄悄跳过。
